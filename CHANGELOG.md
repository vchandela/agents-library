# Changelog

## [Unreleased]

### Changed
- One voice for everything a person reads: every skill now writes with the `explain-simply` skill instead of applying `references/writing-voice.md`, `references/machine-tells.md` or `references/explaining.md` directly, and those three are kept only under explain-simply. `write-spec` and `write-plan` invoke it before each draft and revision. `write-spec` no longer has a required Ambition section (ambition stays in the interview), and each spec section must earn its place. Source: Vivek, 27 Oct, on a spec he called terse and an Ambition section he called useless.

### Added
- `references/core.md`: six core actions that hold in every session, and the only place their words live. Install it as `~/.claude/rules/core.md` (README, Install), which Claude Code re-injects from disk after every compaction. Source: the office-laptop transcript review of 25 Oct 2026. In 145 of 202 compactions across 47 sessions, no reference came back (none re-attached within 30 lines, none read again within 500), and unchecked claims stayed at about 30% of candidates before and after a CLAUDE.md rule on 16 Oct. Every coding agent checked has an always-on tier (Claude Code, Kiro, Cursor, Windsurf, Continue, Cline, Copilot, Codex, Gemini CLI), and obra/superpowers re-injects its core on compaction. engineering-principles, writing-voice, respect-human-attention and judgement now point to it ("The step is `references/core.md` rule N"), and the 21 skills that rely on those name it.
- `analyze-agent-transcripts`: `scripts/digest.py` shrinks a session before a reader goes through it (360 MB to 7.6 MB for the largest), the report adds "Did the last changes work?", helpers each get their own folder, and an event seen by an author and its reviewer counts once.
- `references/setup-facts.md`: the setup facts a repo's agent file states once (how to run the checks, the commit identity the deploy host accepts, generated files and their generator, shell and OS differences); `setup-repo` points to it.
- `ledgers/transcripts.md`: which sessions `analyze-agent-transcripts` has already read, one section per laptop (ids, dates and line counts only, since the repo is public). The skill reads it first, skips what is listed, reads a grown session from its last line, updates the ledger after each batch, and drops lines whose transcript file is gone from that laptop. The skill also checks `cleanupPeriodDays` on each laptop (Claude Code's default of 30 days would delete sessions before a run every few months) and offers to set it to 120. A new Pacing section: the run may use 30% of what is left in the five-hour window when it starts (stop line `start + 0.30 × (100 − start)`, never above 80), works in batches of about 4 sessions, checks the usage meter before each batch, saves notes and ledger lines after each, and reads Sonnet 5.5 readers only. A setup section gives the status line lines that save the meter to `~/.claude/state/usage.json` on each laptop.
- `references/agent-prompts.md`: how to write text a model runs (workflow and system prompts, sub-agent briefs, tool descriptions, skill bodies), from Anthropic's engineering posts, the Opus 5 and 5.5 prompting guides, the skill authoring guide and OpenAI's gpt-5.5 and 5.6 guidance. The reason goes in the same sentence, firm words are kept for real limits, generic self-checks are dropped on Opus 5 (they cause over-verification) and written-out reasoning is not requested (Opus 5.5 can refuse it), absence of evidence is not a no, sub-agent briefs carry objective, format, tools, boundaries and a return size, and review prompts find everything and filter afterwards. Ends with an 11-item checklist. `review-pr` runs it on any diff that edits a prompt, `setup-repo` adds it as layer 6, `evals` applies it when a prompt is under test. Every rule read is sorted in `docs/ledgers/anthropic-prompting.md`.

- `references/engineering-principles.md`, First principles: long-term where it is cheap and proven in the company, otherwise pragmatic behind a seam, with the long-term choice always written down. `references/ambition.md`, Depth: go broad on what the job needs and ask, rather than assume a no; others cut. Source: 0aa9c184, 27 Oct 2026 (tool layer design).

- Check everything by default (`references/core.md` rule 2, `engineering-principles`, `explain-simply`, `research-prior-art`): "not checked", "a guess" and "I left it out" are no longer acceptable answers; an unreachable check becomes a blocker with the access asked for. Source: 0aa9c184, 27 Oct 2026, user: "You have to check each and everything that's the default."

- `explain-simply`: pages are a story written for a colleague opening them cold. Pick one of two arcs before the first diagram, the diagram is the core and text its satellite, proof sits beside each claim, every step unlocks the next, headings retell the story, the problem-and-fix page as a device, and three checklist lines (structure without text, a cold-reader sub-agent test, no "not checked"). Borrowed from humanlayer show-me, mattpocock grilling and wait-what, anthropics doc-coauthoring, obra/superpowers, Randy Olson's And-But-Therefore; ledger in `docs/ledgers/explain-skills.md`. Source: 0aa9c184, 27 Oct 2026.

- `explain-simply` (visuals, explaining): flows read left to right with peers stacked vertically and groups labelled by owner; each key idea once in its best form, reusing the author's own charts; an opening sentence with one or two concrete examples; one word per idea once defined; decisions and open questions in one closing section, settled first. Source: 0aa9c184, 27 Oct 2026, review of the Shared Tool Layer page.

### Changed
- `chief-of-staff`: `setup-machine` installs a daily launchd timer (07:00 on the laptop's clock) that runs `rc-reconnect`, so the coordinator no longer runs it at each session or brief; it reads the log when asked and runs the script by hand only after an account switch. Sessions without a tmux marker in ListAgents are the ones to move into tmux. A run of `rc-reconnect` now ends with one dated line, so a log shows the timer ran; `setup-machine --check` also fails when the timer file is right but the job is not loaded. The Amphetamine list no longer includes Enable Statistics, which the app resets on every launch and which made each run quit and relaunch it.
- Reviewers block only on a shown failure: a finding is required only with a repro or `file:line` against the contract or correctness, only required findings start a round, round 1 lists everything and later rounds check the fixes, and an approval needs green CI on the exact head plus a real run or sample for code that touches real data (`ship`, `references/handoff-protocol.md`). Source: e56396ef ran 28 rounds on one artifact; ce4ad34e L1452; f83d53ec L15721; Claude Code best practices on reviewers that over-report.
- `references/judgement.md`: when two of the user's instructions pull against each other, ask which wins once, with your pick. Source: dd382a4b L12229.
- README "Writing a skill": a mid-session correction gets a search of the library and one eval case from the real moment before it becomes a rule, with the session id and line in the CHANGELOG; rules are retired at each model release only if they help none of the models in use (today Sonnet 5.5 and Opus 5.5); skills change by small edits, never a whole rewrite (arXiv 2510.04618); and how a rule enters and leaves core.md. Source: 0aa9c184 L13917 and L16463, 5b2ad6a2 L63875 and L65536, f83d53ec L8447, a1a1d8b5 L15109.
- `scripts/sync-references.sh` copies into each skill only the references it needs (the files its text names, the files those point to, and the subfolder of any in one) instead of all of `references/`, and `--check` fails on a missing, extra or stale copy; the copied files go from 836 to 203, 5.6 MB to 1.7 MB.
- `references/shipping.md`: what sessions share on one machine has an owner and an end; a send is not a delivery; shared bookkeeping files are set at merge time and merge order is stated once.
- `references/testing.md`: fast tier while building, heavy tier once on the final head (pointed to from `implement-plan` and `split-commits`).
- `ship`: before resending, search every copy of what a finding named and read the fix back; a dropped or held send is carried into the next message and something wakes the sender. `implement-plan`: start a long job once in the background.
- `references/research-sources.md`: a fetch result is a lead, never a quote (from the Claude Code tools reference); `write-spec` and `explain-simply` point to it.
- `explain-simply`: explanations go bottom up (start from the smallest piece the reader can picture, one new piece per step), and anything that moves or takes turns is shown as a small stepped animation with Next, Back and Reset, no autoplay and reduced motion honoured (`references/explainer-pages.md`).
- `references/untrusted-input.md`: wrap untrusted text handed to a model in a tag with a random id, plus one line saying its instructions are not the user's.
- `references/evals.md`: "Grading what matters": grade the outcome not the path, partial credit, capability and regression suites, graders that do not reject correct answers over format or accept a claim of done, and cost next to accuracy.
- README "Writing a skill": a description may name what a skill covers in a phrase but never its steps; a skill body follows `agent-prompts.md`; say whether a script is run or read; watch how an agent moves through a skill; test on every model and again after each release, retiring capability skills the bare model no longer needs.
- `scripts/lint-skills.py` fails a name over 64 characters or containing "anthropic" or "claude", and a description containing anything shaped like an XML tag. `ship`'s description no longer does.

- One home for visuals, following Anthropic's skill authoring guide. `references/visual-explanations.md` and `references/visual-catalog.md` merge into `references/visuals.md`: the rules, the 50-form catalog with its chart tools, explain-simply's diagram rules, and a checklist to copy and tick before anything goes out. `explain-simply`, `make-slides`, `write-spec`, `write-plan`, `write-tech-doc` and `research-prior-art` require that checklist in "Done when". The catalog had been named by no skill, only reachable two hops away, which is why pages shipped without charts.
- References stay one level deep from SKILL.md: every skill names each reference its references rely on, and `write-spec`, `write-plan` and `review-plan` list every system-design entry. A pointer for optional depth names the topic in words; a file path means "read this".
- Reference files over 100 lines open with a "## Contents" list (`engineering-principles`, `research-sources`, `ui-quality`, `system-design/index`, `visuals`).
- `scripts/lint-skills.py` fails a skill that relies on a reference it does not name, and a reference over 100 lines without "## Contents".

### Added
- `analyze-agent-transcripts`: reads a batch of your own Claude Code or Cowork session transcripts whole (including tool calls, results and anything the harness saved out to a file) and turns human-written one-line notes into a failure-mode report, with counts and traceable examples. Specializes `evals`'s "look at real data first" step, stops before item-building, judges or gating, and proposes no fixes.
- `references/ambition.md`: Rieseberg's "How to be more ambitious" as one reference the agent applies unprompted (altitude, depth, range, speed, believing it can be done, guards), with a short form in `references/judgement.md` and slots in `write-spec`, `diagnose-bug`, `ship`, `chief-of-staff`, `write-blog`, `research-prior-art` and `setup-repo`. Measured with `evals/ambition-*` (sonnet, 5 runs per case, judge sonnet): 11 of 15 pass against 0 of 15 on main across three tasks, and a small-question case stays 5 of 5 on both. Measured on Opus 5.5 (Opus judge, 30 runs per arm, skills before and after): target floor 0 to 30 of 30, spec reach 0 to 29, outcome altitude 0 to 27, and a small question stays short (26 and 24 of 30, within noise).
- `references/system-design/`: a toolbox for picking mechanisms. `index.md` maps a design problem, written as a plain question, to an entry, and fourteen family files (storage, caching, queues and streams, long-running work, consistency and concurrency, scaling and partitioning, real-time updates, search, large files, counting and aggregation, APIs and the edge, ML systems, code structure, numbers) give each tool's use, its wrong fits, the choice it forces and how it fails, with links to the lessons it came from. `write-spec`, `write-plan` and `review-plan` point at the index.
- `make-slides`: reading or speaking deck first, an agreed outline of title claims and evidence, the answer first for an exec deck, one point per slide, split rather than shrink, Google Slides API traps, and a thumbnail check of every slide. It runs explain-simply for the content. Every rule from the eleven source files is sorted in `docs/ledgers/make-slides.md` as covered, taken or refused, with the reason.
- `ship`: one command runs spec, plan and stacked PRs, with a separate reviewer session on each stage and the user approving every stage. Rounds continue until the reviewer approves, and it stops for the user only on a disagreement about requirements. It moved here from a local copy.
- `design-ui`: the order of work for a new screen (the job, the repo's tokens, a state grid, build, a look at every width and theme), judged against `references/ui-quality.md`.
- `diagnose-bug`: a red-capable loop before any theory, ranked hypotheses, one variable at a time, the fix at the shared point, and a stop after three failed fixes.
- `review-security`: a six-part bar for a finding, three verdicts, severity capped by shown impact, and a full audit with a ledger and refuting verifiers.
- `references/machine-tells.md`, `references/ui-quality.md`, `references/shipping.md` and `references/security-attack-classes.md`.
- `references/research-sources.md`: the eight source types, engineering blogs to target, access workarounds, the sub-agent and fact-check prompts, the authority score, and the report shape.

### Changed
- Compaction pass across the library (about 4,300 words cut): each shared rule now lives in one reference and skills point to it (stacked-PR merging in `stacked-prs.md`, research prompts and report shape in `research-sources.md`, judge checking in `evals.md`, page length in `visual-explanations.md`, PR descriptions in `engineering-principles.md`); credits, source links and backstories moved out of the working text into `docs/references.md` and `docs/ledgers/evals.md`. Review rounds have no count limit (`handoff-protocol`), and an option card carries your marked pick (`respect-human-attention`).
- `engineering-principles` links correct by construction to one status field over contradictory flags. `scripts/lint-skills.py` now checks reference paths inside subfolders, such as `references/system-design/index.md`.
- Pages (artifacts) stay tight: as few visible words as possible (the 1,100 word budget was dropped on 25 Oct 2026, complete sentences and a coherent explanation kept), diagrams and Now versus Fix panels carry the explanation, at most two sentences under each diagram, no lede, no recap and no conversation history. Each point gets a collapsed "Explain simply" dropdown with its plain-words version, and each item is reviewed for value before it earns a place. New section "Length: diagrams carry the page" in `visual-explanations`, pointers in `writing-voice`, `explainer-pages` and `explain-simply`.
- From the make-slides ledger, shared rules go where they belong: no decorative pictures and a charts and screenshots section (`visual-explanations`), same-renderer previews and working links (`preview`), no centred paragraphs and 3:1 for meaningful graphics (`ui-quality`), two new tells (`machine-tells`), situation then change then answer, and the cost of doing nothing (`writing-voice`), bad news first and stories only from the user (`respect-human-attention`), and yardsticks and verbatim quotes (`explaining`).
- `engineering-principles`: errors never go silent. A key error records its failure where the data would have been, logs, and reaches a human through the repo's existing alert route. A non-key error only logs.
- `explain-simply`: end a step-by-step walk with what the facts mean for the decision, and draw the boundary when the question is who can reach what.
- `ui-quality` and `design-ui` add what good-css.com and seven public design skills check that ours did not: 16px inputs and no zoom lock, long unbroken text, sticky and full-height layouts, unclipped overlays and native dialog and popover, `color-scheme`, token-pair contrast, outline focus rings, keyboard overlays and live regions, hover only on hover devices, fields that keep their size, a pause control for motion, axe-core, settled captures, and a fresh reviewer for the finished screen.
- Trigger tests are measured with `claude plugin eval`: seven cases in `evals/` pit neighbouring skills against each other (design-ui, qa-live-site, review-product-page, review-pr, review-plan, explain-simply, write-tech-doc). Baseline on 2.1.286 with Opus 5.5: 21 of 21 runs right.
- README: name the case the model would do alone, end the turn where a spec or plan ends, keep the reason in every rationalisation row, put the must-survive rule first, and isolate eval runs outside any git repo.
- `use-your-judgement` and `stop-decide-hold` merge into `references/judgement.md`. Reference headers lose their "Applied by" lines, which kept going stale.
- write-spec, write-plan and review-plan point at `writing-voice` and `visual-explanations` instead of restating them. Settled: open items in a doc carry the user's preference, not the agent's pick; a working spec runs to 3 pages and the team's review page 1 to 2; an explainer walks steps first for a new reader and shows the map first to someone judging a design; a PR body is full sentences, then Evidence and Merge danger.
- The linter allows `license` and `disable-model-invocation`, and fails on an unescaped `$ARGUMENTS` in a body.
- `use-your-judgement` opens with the test every piece of work must pass: it moves the user's goal forward or removes a blocker, or it is parked.
- `references/explaining.md` is the one home for how to explain (ground up, an example per claim, decisions side by side, questions answered where they arise, and the devices that landed with real readers). `explain-simply` drops from about 2,700 words to 1,400 and `understand-codebase` loses its drifting copy of the same rules. `preview.md` says a Markdown document in a repo needs only its diagrams parsed and one rendered read.
- Every pipeline skill takes what held up from eight public skill repos: see `docs/references.md` for each idea's source and what was refused. `testing` gains a claim and evidence table; `engineering-principles` a ladder, a never-cut floor and keep or revert performance work; `handoff-protocol` what a reviewer receives; `visual-explanations` a form chooser, a budget and diagram grammar; `write-spec` interviews in rounds.
- `qa-live-site` and `split-commits` now carry `references/`.
- `respect-human-attention` covers the systems a skill designs: list every human touchpoint, ask a person only when a machine can't decide, in a place they already work, with evidence attached. `write-tech-doc` and `explain-simply` now apply it.
- `explain-simply` and `write-tech-doc` add one page shape for designs with a handful of parts: problem first, a big-box map, nested layers per part, one real case through every section, and state diagrams for lifecycles. Marked as one shape among several.
- `research-prior-art` adds an exhaustive per-company sweep (inventory every post from sitemaps, feeds and GitHub before reading, then read each in full), checks that each citation points at the right page, and ends reports with numbered references and every source grouped by company, both collapsed.
- `research-prior-art` maps a whole landscape: a confirmed brief, one parallel sub-agent per source type, merge by idea, a mandatory fact-check agent, authority badges counted by organisation, and a step-by-step report.
- Skills carry real copies of `references/` instead of symlinks, so a single skill folder works on its own. `scripts/sync-references.sh` regenerates the copies, and a CI check fails when one is stale.
