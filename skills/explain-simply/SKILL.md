# Explain simply

Explain from first principles, with examples grounded in reality.

**The bar is hard: easy to digest without losing technical depth.** Simplifying by removing the difficult part is not this. Keep the depth, change the delivery.

## How

- Start from what is fundamentally true, not from the vocabulary.
- Define every term the first time it appears, in plain words. Never leave jargon standing.
- Give an analogy or a concrete example for anything abstract.
- Build up. Each idea should rest on the one before it.
- Assume a beginner. Assume an intelligent one.

## Do not

- No hand waving. If you cannot explain how it works, say that you cannot.
- No fluff, no filler, no throat clearing.
- No skipping the hard part. The hard part is usually why they asked.

## Format

FAQs work well for clearing specific doubts. Diagrams and tables work well for anything with parts or steps.

Apply `references/writing-voice.md`.

## Check

Would somebody who did not already know this understand it on one read? If the explanation only makes sense to someone who already gets it, it has not worked.
